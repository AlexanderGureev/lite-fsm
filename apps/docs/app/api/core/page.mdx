# Core API

`@lite-fsm/core` — runtime без привязки к UI-фреймворкам.

## Импорт

```ts copy
import {
  MachineManager,
  createActorMeta,
  createConfig,
  createEffect,
  createMachine,
  createReducer,
  definePlugin,
  defineMachine,
  Machine,
  LiteFsmError,
} from "@lite-fsm/core";
```

## Machine config

> Reducer в примере написан в стиле Immer: при запуске такой машины через `MachineManager` подключите `immerMiddleware`. Без middleware reducer должен вернуть новый объект `{ state, context }`.

```ts showLineNumbers copy
import { createMachine } from "@lite-fsm/core";

const counter = createMachine({
  config: {
    IDLE: { INC: "IDLE", RESET: null },
    "*": { BOOT: "IDLE" },
  },
  initialState: "IDLE",
  initialContext: { count: 0 },
  reducer: (slice, action, { nextState }) => {
    slice.state = nextState;
    slice.context.count = action.type === "RESET" ? 0 : slice.context.count + 1;
  },
});
```

| Поле                     | Назначение                                                                   |
| ------------------------ | ---------------------------------------------------------------------------- |
| `config`                 | Граф `{ [state]: { [eventType]: target } }`; `"*"` задаёт резервные переходы |
| `initialState`           | Стартовое состояние                                                          |
| `initialContext`         | Стартовые данные машины                                                      |
| `reducer?`               | Собирает следующий `{ state, context }`                                      |
| `effects?`               | Синхронные или асинхронные effects для нового state или `"*"`                |
| `hydrate?`, `dehydrate?` | Кастомная транспортная форма snapshot                                        |
| `groupTag?`              | Тег actor group для actor template                                           |
| `persistence?`           | Actor persistence: `"runtime"` или `"snapshot"`                              |

## Targets

| Target                                          | Поведение                                                                                     |
| ----------------------------------------------- | --------------------------------------------------------------------------------------------- |
| `"NEXT_STATE"`                                  | Переход в указанное состояние                                                                 |
| `null`                                          | Переход без смены state: reducer получает action, effect для конкретного state не запускается |
| `undefined` или отсутствующий ключ              | Action игнорируется                                                                           |
| `"__RESOLVED"`, `"__REJECTED"`, `"__CANCELLED"` | Terminal target actor template                                                                |

Явный `config[state][type]` имеет приоритет над wildcard `"*"`.

## Factories

| API                     | Назначение                                       |
| ----------------------- | ------------------------------------------------ |
| `createMachine(cfg)`    | Типизированная фабрика полного machine config    |
| `createConfig(cfg)`     | Типизированная фабрика графа переходов           |
| `createReducer(fn)`     | Типизированная фабрика reducer-а                 |
| `createEffect(opts)`    | Обёртка effect с `every` или `latest` семантикой |
| `createActorMeta(meta)` | Замороженный `Readonly<ActorMeta>`               |
| `definePlugin(plugin)`  | Объявляет plugin value для `MachineManager`      |

`createEffect`:

```ts showLineNumbers copy
import { createEffect } from "@lite-fsm/core";

const load = createEffect({
  type: "latest",
  effect: async ({ transition }) => {
    transition({ type: "DONE" });
  },
});
```

## MachineManager

```ts showLineNumbers copy
import { MachineManager } from "@lite-fsm/core";

const manager = MachineManager(
  { counter },
  {
    schemaVersion: 1,
    onError: console.error,
  },
);

manager.transition({ type: "INC" });
```

### Опции

| Опция                      | Назначение                                      |
| -------------------------- | ----------------------------------------------- |
| `middleware?`              | Цепочка middleware для пользовательских actions |
| `plugins?`                 | Tuple plugins; расширяет типы текущего manager  |
| `snapshot?`                | Начальный snapshot                              |
| `schemaVersion?`           | Версия snapshot                                 |
| `onError?`                 | Ошибки effects и `condition`                    |
| `onUnknownMachineKey?`     | Неизвестный ключ машины при hydrate/snapshot    |
| `onSchemaVersionMismatch?` | Несовпадение schema version                     |
| `originId?`                | Префикс источника id для распределённого spawn  |
| `generateActorId?`         | Функция генерации actor id                      |
| `generateGroupId?`         | Функция генерации group id                      |

### Методы

| Метод                               | Назначение                                                       |
| ----------------------------------- | ---------------------------------------------------------------- |
| `transition(action)`                | Отправить событие через middleware/reducer/effects pipeline      |
| `getState()`                        | Получить состояние manager после завершённого перехода           |
| `getSnapshot()`                     | Получить текущий snapshot без пользовательских `dehydrate` hooks |
| `onTransition(cb)`                  | Подписаться на успешные transitions                              |
| `setDependencies(depsOrUpdater)`    | Задать effect dependencies                                       |
| `replaceReducer(enhancer)`          | Обернуть root reducer                                            |
| `dehydrate(opts?)`                  | Собрать снимок для передачи или сохранения                       |
| `hydrate(snapshot, opts?)`          | Применить снимок                                                 |
| `getHydratedState(snapshot, opts?)` | Рассчитать состояние после `hydrate` без изменения менеджера     |

## Plugins

Plugin — объект с `name` и `install(ctx)`. `definePlugin(...)` не меняет runtime-значение, но фиксирует тип capabilities и сохраняет literal `name` при обычном вызове.

```ts showLineNumbers copy
import { MachineManager, definePlugin } from "@lite-fsm/core";

const auditPlugin = definePlugin<
  {
    manager: {
      audit: {
        machineKeys: () => string[];
      };
    };
  },
  "audit"
>({
  name: "audit",
  install(ctx) {
    ctx.manager.extend("audit", (runtime) => ({
      machineKeys: () => Object.keys(runtime.config),
    }));
  },
});

const manager = MachineManager(
  { counter },
  {
    plugins: [auditPlugin] as const,
  },
);

manager.audit.machineKeys();
```

Жизненный цикл фиксирован: `MachineManager(...)` сначала устанавливает встроенный default runtime preset, затем вызывает пользовательские `install(ctx)` один раз и в порядке массива `plugins`, после этого валидирует машины и собирает runtime state. Встроенный preset регистрирует storage kind `"instance"` и остаётся частью `@lite-fsm/core`; public API для custom runtime presets пока не публикуется.

`PluginCapabilities` описывает только типовую поверхность текущего tuple `plugins`: `transitionEvents` расширяет `manager.transition(...)`, `actionMeta` расширяет служебный `action.meta`, `machine` используется в typed `createMachine` wrapper, `deps` и `transition` доступны только в effect/reaction deps, `manager` добавляет поле на returned manager object. Непустой machine extension обязан задавать `storage`. Plugin-specific события не добавляются в `MachineEvents<S>` и не становятся событиями обычного `createMachine<AppEvents>(...)`.

```ts showLineNumbers copy
import { createMachine, type EffectDeps, type LiteFsmPlugin, type TypedCreateMachineFn } from "@lite-fsm/core";

type AppEvent = { type: "START" } | { type: "DONE" };

type TestStorageExtension = {
  storage: "test";
  input: {
    test: { key: string };
  };
  publicState: { state: "READY"; context: { key: string } };
};

type TestPluginCapabilities = {
  machine: TestStorageExtension;
  deps: { trace: () => string };
  transition: { finish: () => void };
};

type Plugins = readonly [LiteFsmPlugin<TestPluginCapabilities>];
type AppDeps = EffectDeps<{}, Plugins>;

export const createAppMachine: TypedCreateMachineFn<AppEvent, AppDeps, TestStorageExtension> = createMachine;
```

Plugin-specific machine extensions фиксируются через app wrapper `TypedCreateMachineFn`. Прямой value `createMachine` остаётся совместимым с таким wrapper для assignability, но прямой plugin-specific overload не является публичным способом настройки приложения.

Storage runtime подключается через `ctx.storage.register(kind, runtime)`. Базовый контракт runtime: `kind`, `validateTemplate`, `compileTemplate`, `createRuntimeState`, `createPublicInitialState`, `acceptsEvent`, `reduce` и `commit`. `runtime.kind` и `compileTemplate(...).kind` должны совпадать с registered storage kind. Registry можно менять только синхронно внутри `install(ctx)`. Опциональные capability blocks подключают дополнительные фазы:

| Блок        | Контракт                                                       |
| ----------- | -------------------------------------------------------------- |
| `effects`   | conditions и effect invocations для storage runtime            |
| `reactions` | синхронные реакции после commit и до subscribers               |
| `identity`  | runtime identity для routing и диагностики                     |
| `snapshot`  | `dehydrate` / `hydrate` payload через `snapshot.storage[kind]` |

Если runtime указывает `routeMetaKeys`, plugin обязан зарегистрировать каждый ключ через `ctx.routing.registerMetaKey(...)`. Пользовательские данные должны идти через `payload`; `action.meta` остаётся служебным routing/sender contract.

Manager extension factory получает `ManagerRuntimeContext`. Поле `config` в этом контексте — исходный machine store, переданный в `MachineManager`; extension должен читать его как immutable reference и не мутировать машины.

`dehydrate()` включает storage payloads runtime с `snapshot` capability в top-level envelope `snapshot.storage[kind]`. `dehydrate({ storage: [] })` отключает storage payloads, `dehydrate({ storage: ["test"] })` выбирает только указанные runtimes. `getSnapshot()` не вызывает storage `dehydrate` и не добавляет `storage`.

`@lite-fsm/entities` проектируется как внешний runtime поверх этой plugin system, но entity runtime, `manager.entities`, React entity hooks и graph support для entities не входят в текущий core API.

### Стратегия восстановления

`hydrate(snapshot, { strategy })` не выполняет глубокое объединение поля `context` и не заменяет всё состояние менеджера. В обоих режимах применяются только ключи из `snapshot.machines`. Для доменных машин `strategy` передаётся в обработчик `hydrate` как `meta.strategy`; для акторов, сохраняемых в снимок, `merge` сохраняет акторов вне входящего набора записей, а `replace` удаляет отсутствующих.

## Actors

Actor template определяется через `__INIT` в `config`.

```ts showLineNumbers copy
const request = createMachine({
  config: {
    __INIT: { START: "PENDING" },
    PENDING: { DONE: "__RESOLVED", FAIL: "__REJECTED" },
  },
  initialState: "__INIT",
  initialContext: { id: "" },
});
```

Routing выполняется через `action.meta.actorId`, `groupId`, `groupTag` или sender meta. Подробности: [Акторы](/guide/actors).
